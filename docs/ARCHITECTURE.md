# Устройство androsaur-audio

Статус: каркас, 2026-10-24. Основа — приложение mobile-ledger (камера): те же два
модуля, тот же вид сервера и MCP, чтобы модули Androsaur работали одинаково.

## Слои

| Слой | Где | Что делает |
| --- | --- | --- |
| Логика без Android | `shared` (KMP) | `WakeWordEngine` и `WakeGate` (контракт движка, защита от повторов), `AudioLevel` и `SilenceDetector` (уровень, признак «микрофон занят другим»), `EventLog` (журнал событий) |
| Захват | `MicrophoneListener` | один поток читает `AudioRecord` (16 кГц, моно), считает уровень и время работы движка на кадр, кормит движок |
| Движки | `EngineFactory`, `VoskEngine`, `MicroWakeWordEngine`, модуль `microwakeword` | сменные реализации `WakeWordEngine`; один движок за раз, загрузка в фоне (`engine.state`: loading/ready/failed) |
| Сервис | `AudioService` | foreground-сервис типа `microphone`, владеет захватом, журналом, сервером, mDNS |
| Транспорт | `PhoneServer`, `McpEndpoint`, `NsdAdvertiser` | HTTP (`/status`, `/events`, `/mcp`) на порту 8089, MCP, анонс `_androsaur-audio._tcp` |
| Экран | `MainActivity` | разрешения, старт и остановка, адрес и код доступа |

События: `service_started`, `heard`, `engine_ready`, `engine_failed`, `wake_word`, `microphone_silent`, `microphone_recovered`, `error`.
Клиент читает их по `after=<последний id>`; поток (SSE/WebSocket) добавится вместе с протоколом.

## Движки wake-word

Идентификаторы: `none`, `vosk`, `mww:<модель>`. Выбор хранится в настройках приложения.
- **vosk:** малая русская модель (`vosk-model-small-ru-0.22`, 46 МБ, распаковывается в `filesDir`
  при первом запуске), свободное распознавание по всему словарю; срабатывание — когда в тексте
  подряд слова фразы (`WakePhrase`, по умолчанию `зюзя`, точное совпадение целого слова) (`PhraseMatcher`).
  Фраза меняется через API/MCP (`phrase`), хранится в prefs `audio`/`phrase`, проверяется в `WakePhrase.normalize`
  (только русские буквы, до 4 слов, допуск до 3). Законченные фразы, где есть начало любого слова фразы (первые 4 буквы),
  пишутся в журнал событием `heard`, чтобы подбирать допуск по реальным данным.
- **vosk-grammar:** та же модель, но распознаватель ограничен грамматикой
  списком фраз из настройки (варианты `|` раскрываются, допуски отбрасываются; не больше 16) плюс `"[unk]"`, например `["привет петя", "[unk]"]`. Дешевле по процессору, но любое «привет …» превращается в фразу
  целиком (замечено владельцем 2026-10-24), поэтому оставлен только для сравнения.
- **mww:** потоковая TFLite-модель microWakeWord. Нативный модуль скопирован из Home Assistant
  Android (признаки звука как в ESPHome + TFLite Micro). Модели лежат в `assets/wakeword/`
  (`<имя>.tflite` + `<имя>.json`), новая модель = два файла. Пока только английские тестовые.
- Чтобы сравнивать, в `/status` есть `engine.msPerFrame` против `engine.frameMs`.

## Речь

Интерфейс `Speaker` (`speak`, `measure`, `stop`) и два вида движков, как у wake-word: `PiperSpeaker` (sherpa-onnx 1.13.8, голоса
в assets, при первом запуске голос и данные espeak-ng копируются в `filesDir`, движок читает их как файлы) и `SystemSpeaker`
(`TextToSpeech`; замер через `synthesizeToFile`, рот условный). `SpeakerFactory` собирает движок по `SpeakerSpec`
(`shared`, разбор строки `piper:<голос>` / `system[:<пакет>]`). `SpeechController` держит выбранный движок, очередь из одного
потока, заглушает микрофон (`micMutedUntil`: движок wake-word получает нули) и считает замеры.

Piper пишет звук в `AudioTrack` по мере синтеза; `MouthEnvelope` (shared) считает громкость окнами по 40 мс, а рот берётся по
позиции воспроизведения (`playbackHeadPosition`), поэтому он совпадает со звуком, а не с синтезом. Другие приложения читают
`GET /speech` (`speaking`, `mouth`) примерно 15 раз в секунду, пока идёт речь. Замер: одни и те же десять фраз
(`BenchPhrases`), `rtf` = время синтеза / длина звука (меньше 1 быстрее реального времени); в режиме «вслух» дополнительно
ожидание первого звука. Замеры синтеза идут без воспроизведения, чтобы звук не мешал.

### Диагностика речи без человека

`adb` + два скрипта, ничего не нужно нажимать на телефоне (ввод в экран по `adb` Xiaomi блокирует, токен приложения не нужен):
- `scripts/speech-bench.sh [-p] [-c] [метка:потоки[:движок] ...]`: штатный замер из экрана «Голос» (десять фраз), строка на фразу в logcat
  (тег `SpeechBench`). `-p` говорит вслух и добавляет «до первого звука», `-c` на время замера останавливает камеру. Пример:
  `scripts/speech-bench.sh -p a:2:piper:denis b:4:piper:denis`. Потоки сохраняются как настройка телефона.
- `scripts/speech-say.sh [-t потоки] [-n повторов] [-g пауза_мс] [-x текст]`: фраза через реальный путь ответов; печатает первый звук,
  время синтеза с воспроизведением и длину звука. Нагрузку для опытов создают фоновыми `sh -c 'while :; do :; done'` (потом убить).
Оба работают через `BenchTrigger` (приёмник под системным разрешением `DUMP`: его есть у `adb shell` и нет у обычных приложений).

Что измерено на Redmi (Piper denis, fp32), 2026-11-07:
- чистый синтез при камере: потоки 1 / 2 / 4 дают rtf 0.96 / 0.66 / 0.63; без камеры 2 потока 0.56, 4 потока 0.43;
- первый звук = время синтеза первого предложения (библиотека отдаёт звук по предложениям), не зависит от паузы простоя перед фразой;
- под нагрузкой фоновых потоков первый звук фразы в 35 знаков: 1.1 с без нагрузки, 1.3 при 2 потоках, 1.6 при 4, 5 до 8 с при полной загрузке;
- поэтому первое предложение режется по первой запятой (`SpeechSplit`): 35 знаков теперь 0.35–0.45 с без нагрузки и 0.65 при 4 потоках нагрузки.

Сравнение движков на одном телефоне (Redmi, 2026-11-07), фраза «Нашёл, ключи лежат в верхнем ящике на кухне.» (44 знака) через реальный
путь ответа (`scripts/speech-say.sh -e <движок>`), и `rtf` по десяти фразам (`scripts/speech-bench.sh -p`):

| Движок | Первый звук | rtf | Фраза в 101 знак готова за |
|---|---|---|---|
| `system:com.github.olga_yakovleva.rhvoice.android` (RHVoice 1.18.4) | 242 мс | 0.07 | 0.46 с |
| `system:com.google.android.tts` | 379 мс | 0.12 | 1.0 с |
| `piper:denis` (с разбиением по запятой) | 554 мс | 0.5–0.65 | 3.3 с |

Оговорки: у системных движков первый звук — момент `onStart` от системы, реальный звук по микрофону не мерили, а при повторных фразах подряд он падает до 5–7 мс (при первой после паузы 242–267), то есть неустойчив; поле `first` в
`speech-bench.sh -p` для них даёт 3–10 мс и ему верить нельзя, для первого звука брать `speech-say.sh`. Качество голоса цифрами не
оценить: решение по слуху владельца (2026-11-07 выбран RHVoice).

RHVoice на телефоне: приложение с F-Droid (`com.github.olga_yakovleva.rhvoice.android`), голоса качаются внутри приложения («Языки и
голоса») с `rhvoice.org` (хостинг Render; из сети владельца без VPN не открывался: таймаут на 443, и с телефона, и с сервера). Установка
APK из `adb` на Xiaomi блокируется (`INSTALL_FAILED_USER_RESTRICTED`): файл кладут в `/sdcard/Download` и ставят вручную. Другой путь
получить голоса: GitHub `RHVoice/<голос>-rus`, релизы с `data.zip` (формат для Android-приложения не проверялся).

Известное: sherpa-onnx 2.x (2.0.0) выбрасывает espeak из C++-части; для Piper нужен 1.13.x. Ограничения голосов:
`irina` без явной лицензии набора, `ruslan` только некоммерческое использование.

## Решено (из brief)

- Микрофон монопольный, читает только этот модуль, остальным отдаёт события.
- Пакет `dev.hram.androsaur.audio`, название «Androsaur Звук», mDNS `_androsaur-audio._tcp`.
- Доверие: подпись одним ключом и разрешение `dev.hram.androsaur.audio.permission.CONTROL`
  (`signature`); сервис для этого объявлен `exported`. Проверено 2026-10-24 на Redmi 12 (Android 15): главное приложение
  `androsaur` запускает сервис из переднего плана и получает порт и токен через `LinkProvider`
  (`content://dev.hram.androsaur.audio.link`, вызов `link`, под тем же разрешением); дальше обычный HTTP на localhost.

## Что в каркасе выбрано без решения владельца (можно менять)

- Порт 8089 и Bearer-код, как у камеры. Общий код сервера пока скопирован;
  вынести его стоит в `androsaur-protocol`, когда тот появится.
- Источник звука `VOICE_RECOGNITION`, кадр 512 отсчётов по 16 кГц, пауза между
  срабатываниями 2 с, «микрофон занят» после 2 с нулей подряд.
- Журнал на 200 событий в памяти, после перезапуска пуст.

## Не сделано / открыто

1. **Движок wake-word** — Porcupine (ключ доступа, русское слово через Picovoice Console)
   или открытый (русскую фразу обучать). Подключается реализацией `WakeWordEngine`.
2. **Запуск из фона на Android 14–15.** Сервис с микрофоном нельзя поднять из фона;
   нужны `PendingIntent` от видимого главного приложения или роль `VoiceInteractionService`.
   Проверять первым делом на Redmi 12 / Android 15 и одном старом телефоне.
3. Автозапуск после перезагрузки, исключения из оптимизации батареи (MIUI).
4. Речь сделана (см. раздел «Речь»), но не сделано: общий динамик с другими приложениями (фокус звука), речь по частям длинного текста без пауз при rtf выше 1, эхоподавление вместо заглушения микрофона (владелец не сможет перебить ассистента словом).
5. Кто управляет сервоприводами — не решено; в этом модуле их нет.
6. Проверено на Redmi 12 (Android 15), 2026-10-24, при открытом приложении: сервис поднимается как
   foreground типа microphone, микрофон читается (около 31 кадра/с, реальный уровень), `/status`,
   `/events` и MCP отвечают, без Bearer 401, с Origin 403, mDNS регистрируется. Не проверено:
   запуск из фона, перезагрузка, выключенный экран, работа рядом с камерой, два приложения на микрофоне.
